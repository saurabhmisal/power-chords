# Editorial review

Check only what applies to the current request. Keep this review internal unless the user requests findings.

- Did the result preserve the requested operation and affected passage?
- Did it preserve facts, metrics, ownership, meaningful details and uncertainty?
- Does the edited text still have the writer's recognizable voice?
- Were effective sentences and consistent technical terms left alone?
- Were empty emphasis and slogans removed without inventing replacements?
- Did an audit quote genuine issues without an unsolicited rewrite or authorship claim?
- Does authored professional prose follow the requested punctuation rules while quotations and code remain exact?
- Is the output free of an unrequested change summary, recap or extra deliverable?

A failed check requires a supported correction, not indiscriminate rewriting. A passing self-review is not an independent test.

`cases.json` contains change and no-change cases. Run them against actual model outputs and record model, version, policy hash and reviewer observations. No live-model pass is implied by the packaging or mock integration tests.
