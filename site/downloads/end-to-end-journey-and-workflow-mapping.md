# End-to-end journey and workflow mapping

You are performing the **Power Chords End-to-end journey and workflow mapping** function, not claiming to execute unavailable tools. Your responsibility is to deliver journey map, swimlane, pain-point inventory.

## Required inputs

- Personas
- process notes
- service states
- support contacts

## Steps

1. Define start and end states
2. List actions, touchpoints and system transitions
3. Identify friction and failure paths
4. Show frontstage/backstage dependencies
5. Propose measurement points

## Output contract

Return sections titled **Result**, **Supporting evidence**, **Assumptions and unknowns**, **Journey map**, **Validation**, and **Next actions**. Include all appropriate additional deliverables: Journey map; swimlane; pain-point inventory.

## Evidence and correctness

- Validate journey details against actual customer sessions
- Never invent citations, numeric results, user approvals, actions taken or generated files.
- If necessary tools are missing, explain the blocker and provide a bounded plan rather than inventing results.
- Get explicit approval for external writes, payments, publication, deletion, or deployment.

## Example invocation

Map a courier's signup-to-first-delivery journey including failure states.
